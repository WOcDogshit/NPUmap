# 导航信息上「小米超级岛」· 可行性分析

> 结论：**微信小程序目前无法把导航信息投到小米超级岛**。这是平台限制，不是代码问题。

## 一、为什么不行

1. **小程序运行在微信的"沙箱"里**：小程序的代码跑在微信 App 内部，只能用微信开放出来的那套 API（`wx.xxx`），不能直接调用手机系统的接口（通知栏、桌面小组件、灵动岛/超级岛）。

2. **微信没有开放"系统实时活动"能力**：微信小程序的 API 列表里，没有任何能把内容推到系统通知栏 / 锁屏 / 超级岛的接口。`wx.requestSubscribeMessage` 只能发**微信内部的订阅消息**（模板消息），不是系统级的实时导航。

3. **超级岛要求系统级实时活动**：小米超级岛（HyperOS 实时活动）需要 App 调用小米开放平台的系统接口（LiveCard / 实时活动 API），微信小程序拿不到这个权限。

> 一句话：**微信小程序 = 住在微信家的房客，不能往房子外面贴东西。**

## 二、真正能做到「上超级岛」的路径

把小程序的**核心功能迁移成安卓 App**（原生 Kotlin，或 uni-app / Flutter 打包），然后接入小米开放平台的**实时活动（LiveCard）**接口：

| 方案 | 说明 | 成本 |
| --- | --- | --- |
| 原生 Android（Kotlin） | 直接调系统 LiveCard API，最稳 | 高，需重写 UI |
| uni-app 打包 App | 用现有 Vue/JS 逻辑，DCloud 有原生插件市场 | 中 |
| Flutter | 跨平台，有 live_activity 类插件（小米适配看插件支持度） | 中高 |

导航实时活动要做的事（App 端）：
- 导航开始后，把「当前指引 + 剩余距离 + 剩余时间」推给系统实时活动
- 定位变化时**更新**实时活动内容（小米会把它显示在超级岛/锁屏）
- 导航结束、用户退出时**关闭**实时活动

> 好消息：**我们的地图、路线、导航算法逻辑全部可以复用**，迁移主要是换 UI 层 + 加实时活动接口。

## 三、小程序内能做的「替代增强」（零成本，现在就能做）

1. ✅ 导航信息大字常驻（已做：当前指引 + 剩余距离 + 时间）
2. ⏳ 微信**订阅消息**：导航结束时给用户发一条微信通知（模板消息，需要服务端 + 用户订阅，不是实时）
3. 💡 引导用户**把小程序加入微信浮窗**，切出去后从浮窗快速回到导航页

## 四、建议

- **短期**：把小程序内的导航体验做扎实（已基本完成）
- **中期**：如果真想要超级岛，用 uni-app 把现有逻辑打包成 App，再接小米 LiveCard —— 需要你注册小米开放平台开发者账号，我可以帮你把代码结构准备好
- 想清楚是否值得：校园导航的**核心使用场景是打开小程序看路线**，超级岛属于锦上添花
